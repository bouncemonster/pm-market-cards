# Работа агента — PM Market Product Cards

## Назначение и источник

Это `bouncemonster/pm-market-cards`: библиотека товарной инфографики, не приложение магазина и не база актуальных цен. Актуальный источник — собственная текущая ветка GitHub. Прочитайте [README.md](README.md) и проверьте конкретные изображения до правок.

Не путайте проект с `pm.market`, где находятся операции импорта каталога. Локальные выгрузки, папки дизайнера и старые экспорты не заменяют GitHub автоматически. Для просмотра не нужно устанавливать npm-пакеты или запускать сервер приложения.

## Главное соответствие

**Идентификатор товара → точный вариант → постоянный путь изображения.** Сначала установите бренд, модель или оттенок, объём и вариант упаковки. Не переносите сведения соседнего товара только из-за похожего названия.

Опубликованные пути могут использоваться внешним магазином. Не переименовывайте и не перемещайте изображения ради красивой структуры без проверки потребителей. Совпадение хеша означает одинаковые байты, но не доказывает, что товарные записи можно объединить: один материал может намеренно использоваться для нескольких вариантов.

Перед изменением файла прочитайте его текущую GitHub-версию и проверьте ожидаемый SHA. При конфликте изучите новую версию; не перезаписывайте чужую работу старым файлом.

## Визуальная проверка

Проверяйте целое изображение и текст в исходном разрешении, затем читаемость в размере реальной карточки. Контролируйте пропорции, обрезанные края, правильность товарного варианта, артефакты экспорта и соответствие расширения формату.

В README показывайте существующие разрешённые материалы с понятной подписью. Не выдавайте сгенерированную упаковку за фотографию реального товара и не добавляйте непроверенные цены, остатки, характеристики или обещания результата. Не собирайте всю библиотеку в тяжёлую галерею одной страницы.

## Несколько IDE и продолжение задачи

Перед работой прочитайте текущий issue или handoff и проверьте локальные изменения:

```sh
git status --short --branch
git diff --stat
```

Установите владельца затронутых файлов. Другой агент может продолжать экспорт после завершения его чата. Не удаляйте временные или неотслеживаемые файлы автоматически, не останавливайте чужие процессы и не отправляйте всю локальную папку поверх GitHub.

Делите работу по конкретным товарам или группам с непересекающимися путями. Общий README и навигацию меняет один согласованный исполнитель. Доступ к этой библиотеке не даёт права изменять цены, импортировать каталог или публиковать материалы в магазине.

## Результат и передача

В существующей записи задачи сохраните исходную ревизию, идентификаторы товаров, точные пути, визуальные проверки, опубликованный коммит и результат чтения файлов обратно из нужной ветки. Укажите незавершённые экспорты, чужие правки и одно следующее действие.

Разделяйте «файл опубликован», «изображение просмотрено», «проверено в магазине» и «не проверено». Здесь нет заявленной автоматической проверки приложения; не придумывайте `npm test` или зелёный CI. Права на бренды и материалы сохраняются, новая лицензия этой инструкцией не вводится.
